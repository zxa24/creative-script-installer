# 第 3 组 — 检查与修复

**这些是工具，不是步骤。** 有东西坏了、或想看看改了什么时，拿一个出来。

`3.1` 和 `3.2` 是**一对** —— 前者捕获状态，后者恢复它。批量改动*之前*跑 `3.1`，*之后*跑 `3.2`。

## 3.1 Snapshot Before Apply {#snapshot-before-apply}

*源文件：`snapshot_before_apply.idjs`* —— **与 [`3.2`](#repair-after-apply) 配对**

**为每个可修复的文章捕获一份「之前」快照，并撑大装不下 CJK 文本的框。**

在任何批量文本替换或 CJK 样式应用**之前**运行。它：

1. 撑大那些被几何拆分、短到装不下一行 CJK 文本的框。不管的话，那些框会在重排后变空。
2. 为每个可修复的文章捕获一份「之前」快照。
3. 把快照存两份 —— 一份 `before_snapshot_latest.json`，一份 `<文档名>_before_snapshot.json`。

[`3.2 Repair After Apply`](#repair-after-apply) 读那个文件，把它当作要恢复到的目标状态。

## 3.2 Repair After Apply {#repair-after-apply}

*源文件：`repair_after_apply.idjs`* —— **与 [`3.1`](#snapshot-before-apply) 配对**

**读取 `3.1` 的快照，修复批量改动扰乱的部分，并写一份验收报告。**

预期的顺序：

1. [`3.1 Snapshot Before Apply`](#snapshot-before-apply) —— 存下「之前」快照并撑大短框。
2. 做批量改动 —— 文本替换、CJK 样式导入，随便什么。
3. `3.2 Repair After Apply` —— 读快照、修复、报告。

## 3.3 Relink Missing Links {#relink-missing-links}

*源文件：`relink_missing_from_doc_folder.idjs`*

**在文档自己的目录下任意位置按文件名找到断掉的链接，并重新链接。**

对文档里每一个状态为*缺失*的链接，脚本在**文档目录及其全部子目录**里搜索同名文件，不区分大小写。找到就重新链接并更新。找不到就**报告并留着不动** —— 它从不猜。

- **浅的优先。** 同一个文件名出现在多处时，先取离文档目录最近的那个。这避免它从打包目录里抓出一份深层副本。
- **只管缺失的。** 它处理断掉的链接。文件仍在但被修改过的链接属于*更新*，不是重新链接，不在范围内。
- **有试运行。** 它可以只报告*会*重新链接什么，不碰任何东西。
- **撤销：**所有重新链接包在一个撤销步骤里。
- **搜索上限：**它在 4000 个目录或 12 层深度处停下，并在撞到上限时说明，而不是静默截断搜索。
- **它把报告写到** `<文档目录>/script_outputs/log/`，不可用时退回文档目录本身。

## 3.4 Highlight Translation Changes {#highlight-translation-changes}

*源文件：`track_translation_changes.idjs`*

**把文本与保存的基线做差异，在专用图层上用矩形标出改动的字符。**

高亮是**画在文字后面、单独一层的黄色矩形**。它对文字自身的属性零影响 —— 下划线、字符样式和其他一切都不动。

### 模式

| 模式 | 做什么 |
| --- | --- |
| `auto`（默认） | **首次运行：**捕获一份基线，文档没有可见变化。**之后的运行：**逐字符把每个段落与基线比较，标出改动的子串。它总是先清掉上一次的覆盖层，所以旧标记不会堆积。 |
| `clear` | 删除高亮图层及其上的一切。基线文件保留。 |
| `rebaseline` | 清掉覆盖层，然后把基线重新捕获为新的基准。 |

### 选项

- **忽略空白** —— 抑制那些插入或删除的字符纯为空白（空格、制表、换行、不间断空格、全角空格）的高亮。**默认关闭**；只关心内容改动、想忽略翻译后空白挪动时打开。
- **基线文件** —— 选择与哪个基线 JSON 比较，可以从基线目录的文件下拉里选，也可以给任意路径。捕获模式忽略它，总是写一份新的带时间戳文件。

### 经受结构性编辑

基线首先按位置索引 —— 文章与段落序号 —— 结构没变时这是快路径。当某个段落的文本与该位置的基线条目相差悬殊（段落被增删、序号已错位的迹象）时，它退回按内容指纹匹配。这就是「捕获与比较之间加了 N 个段落」之后文档不至于满屏误报的原因。

## 3.5 Save and Reveal {#save-and-reveal}

*源文件：`save_and_reveal.idjs`*

**当前文档有未保存改动时提议保存，然后在系统文件浏览器里打开它所在的目录。**

一个小便利：运行它，出现保存提示的话回答一下，文档所在目录就在资源管理器或 Finder 里打开。
