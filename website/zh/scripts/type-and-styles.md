# 第 2 组 — 字体与样式

**这些是工具，不是步骤。** 这里没有任何东西属于[正常流程](/zh/guide/workflow)。打开某一个，是因为文档有一个具体的排版问题。

## 2.1 Apply Font Pairing {#apply-font-pairing}

*源文件：`font_apply_panel.idjs`*

**扫描文档的字体，打开一个面板选择跨语言字体配对，并以直接格式应用替换。**

1. 它扫描当前文档，收集在用的字体、它们的字重，以及每种承载了多少文本。
2. 它在 InDesign 里打开一个面板，你在那里设定配对。
3. 按 **Done** 后，它把配对驱动的字体替换作为直接格式覆盖应用。它**不会**为此创建段落或字符样式。
4. 它报告落地了多少处替换。

**撤销：**整批包在一个撤销步骤里 —— 一次 <kbd>Ctrl</kbd>/<kbd>Cmd</kbd>+<kbd>Z</kbd> 全部还原。

## 2.2 Apply CJK Styles {#apply-cjk-styles}

*源文件：`cjk_style_apply.idjs`*

**在可选的文本清理之后，把简体中文供体段落样式及其排版设置导入文档。**

1. 它先问要跑哪些清理 —— 软换行、多余空格、符号/全角标点、合并。
2. 它作用于包含你所选内容的文章，或者文档里每一个可修复的文章。
3. 它打开随附的 CJK 供体文档，把其中的文本样式导入你的文档 —— 这会带来中文排版设置，包括避头尾集 —— 并应用供体段落样式。
4. 它验证供体样式确实带着完整的 CJK 设置到达了，导入若是坏的会大声说明。

**撤销：**导入和应用包在一个撤销步骤里。

::: tip 来源说明
这个脚本没有文件头注释；上面的描述是从其实现读出来的，不是来自声明的摘要。
:::

## 2.3 Set Selection Weight {#set-selection-weight}

*源文件：`set_selection_weight.idjs`*

**把所选文本设为一个命名字重，具体的字体与字重取自品牌配置。**

选中文本，挑一个目标字重，脚本通过品牌配置把那个字重名解析成具体的（字体，字重）对并应用。

- 如果文档还没有那个字重的字符样式，脚本会当场创建一个。
- **中英混合的选区按文字系统分别路由**，各半都拿到正确的字族 —— 全角标点也算在内。
- 已有的段落级覆盖不动；只清除选区内的字符级覆盖。

**失败行为：**大声失败，从不静默。罕见或有歧义的情况会带消息退出，每次退出都有日志。如果应用失败，整次改动作为一个整体回滚，而不是让选区改到一半。

## 2.4 Reorganize Styles {#reorganize-styles}

*源文件：`reorganize_styles_inplace.idjs`*

**按视觉指纹聚类每一个段落，就地把文档重建在一小组生成的段落样式上。**

当文档蔓延出几百个几乎相同的段落样式、或者靠本地覆盖勉强撑着的段落时用它。

它做的：

- 遍历每个文章的每个段落，捕获它的*有效*视觉属性 —— 字体、字号、颜色、行距、缩进、间距、保持选项、项目符号等等。
- 按那个视觉指纹聚类段落。
- 每个簇创建一个把这些属性烧进去的 `_T_p_<hash>` 段落样式。N 个段落通常坍缩成少得多的样式。
- 把每个段落重新指派到它所在簇的规范样式。

它**不**做的：

- 没有源文件选择器 —— 它读当前文档。
- 没有输出文件 —— 它就地修改当前文档。
- **没有 CJK 字体策略。** 它保留原来的拉丁字族。这是纯粹的样式合并，不是翻译准备。

一次运行是这样的：

1. 打开你要合并的文档。
2. 双击脚本。
3. 在它打开的唯一一个对话框里选分组选项 —— 维度、颜色容差、自动合并预设、安全、软换行处理、编辑模式。**取消会干净地中止，不做任何改动。**
4. 等。之后没有别的提示。
5. 一个警告框汇总结果。读一读警告。
6. 检查文档，然后要么保存要么撤销。

**撤销：**整个重组 —— 预检、应用、修复 —— 是一个撤销步骤。

**它还会写：**文档旁边一份进度日志（`<doc>_reorganize_progress_<timestamp>.log`）供事后排查；开着安全选项时，还有一份供后检修复用的「之前」快照。

## 2.5 Repair Cluster GREP {#repair-cluster-grep}

*源文件：`repair_cluster_grep.idjs`*

**重写已建簇样式里的嵌套 GREP 规则，让中性标点不再用错误文字系统的字体渲染。**

它修的问题：在用旧规则集建成的双语文档里，中性标点 —— 比如弯撇号（U+2019）—— 夹在中文簇文档里的拉丁字母之间时，被拉丁 GREP 漏掉了，于是孤零零地留在全角 CJK 字体上。

这个脚本把每个受管簇段落样式的嵌套拉丁与 CJK GREP 规则的 `grepExpression` 重写为当前的、感知上下文的模式，然后重排，让已经落单的标点被重新路由。

- **它是给用旧规则建好的文档的修复。** 新的导入会从流程拿到当前规则；它们不需要这个。
- **它是幂等的。** 再跑一次什么都不重写。
- **撤销：**整次运行一个撤销步骤。

## 2.6 Convert Underline to Rule {#convert-underline-to-rule}

*源文件：`convert_underline_to_rule.idjs`*

**把整段带下划线的段落的字符级下划线替换为段落线。**

它扫描每个文章的每个段落，找出**100% 可见字符**都带字符级 `underline = true` 的那些。对每一个，它移除字符级下划线，改在段落下方放一条段落线 —— 0.5pt、文本宽度、颜色取自下划线字符中占多数的填充色。

**为什么：**字符级下划线跟随每个字形自己的基线。CJK 字形把线藏在字身下面，而拉丁字符和数字把它露出来，于是混排的一行得到一条画了一半的下划线。段落线坐在段落基线上，跨两种文字系统保持连续。

- 它有意放在导入流程之外，让导入保持格式中立，由**你**决定何时应用这个视觉改动。
- **它是幂等的。** 已转换的段落被跳过。
- **它会写**一份日志到 `<文档目录>/convert_underline_to_rule_<timestamp>.log`。
