# 文件与目录

**原则：工作目录是你的；结构化的目录是给脚本的。**

你应该不需要经常打开脚本自己的那些目录。这正是它们存在的意义。工作目录的顶层尽量保持简单。

## 布局

```text
<工作目录>/                      ← 你的，保持简单
  <doc>.indd                      源文档
  <doc>.translated.indd           当前有效的输出 —— 一个固定名字

  script_outputs/                 ← 脚本的目录；你很少打开
    package/                      导出的翻译包
    log/                          运行日志
    report/                       导入报告
    backup/                       导入在覆盖前取的副本
```

顶层只有两个文件，名字永远一样：

- `<doc>.indd` —— 你起步的那份文档。脚本以只读方式打开它。
- `<doc>.translated.indd` —— 当前输出。永远是这一个名字，不带时间戳变体。把你的 PDF 导出、审阅循环和肌肉记忆都指向它。

## 导入对上一份输出做了什么

**导入先把旧文件复制到安全处，再覆盖 —— 如果复制失败，导入就停下，而不是继续。**

当工作目录里已经有一份 `<doc>.translated.indd`，而你再往上导入时，`1.2 Import Translation Package` 会先把那个文件复制到 `script_outputs/backup/`。只有确认副本已在磁盘上，导入才继续覆盖原件。

如果备份做不出来，**导入中止，你磁盘上的文档原样不动**。这是有意的：另一种选择是覆盖掉一份你也许再也造不出来的文件。一次中止的导入是可以恢复的小麻烦；丢失的输出不是。

### 上一版在哪

在 `script_outputs/backup/`。工作目录本身永远只放当前的 `<doc>.translated.indd`，所以回退意味着进那个目录把文件复制回来。

### 这里有一个计划中的改动

备份闸门之所以存在，是因为写入是一次**覆盖**，而覆盖必须被保护。另一种设计能把闸门的必要性整个去掉：先把上一份输出挪开，让名字空出来，写入就变成一次**创建**。

| | |
| --- | --- |
| **备份** —— 脚本今天做的 | 「覆盖前存一份副本。」需要一个每次都必须正确工作的机制；复制失败时写入必须被阻止。 |
| **归档** —— 预期的设计 | 「把上一份挪开，然后写。」没有覆盖，也就没有会失败的闸门。 |

这个改动已经决定但**尚未实现**，所以本页描述的是备份行为 —— 那才是你今天运行导入时真正会发生的事。落地后目录会是 `script_outputs/versions/`。

## 已退役的约定

一个更早、手工时代的约定用阶段编号目录 —— `01_input/`、`02_source/`、`03_working/`、`04_review/`、`05_delivery/`、`logs/`。**那套约定已退役。** 它早于导出/导入包链，也不是脚本写出的东西。

交付侧的处理（旧 `04_review/` 和 `05_delivery/` 的用途）目前**不在**自动化范围内。需要的话另行设置 —— 别把旧的编号目录当作本约定的一部分复活。
